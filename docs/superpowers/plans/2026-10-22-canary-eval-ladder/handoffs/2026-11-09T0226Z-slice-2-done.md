## Rulings

- **No re-provision before the live check.** *Decision:* tasks 1 and 4 ran on the build as it was (frontend
  from `~/spe-frontend/docker-compose.yml`, the layout before `platform/instance/compose.yml`). *Why:* the plan
  rebuilds only when the build predates slice 1's hand-off fields, and `hosts.yml` has them; a rebuild was tried
  anyway and stopped at `agui : LLM key present` (no LLM key on this guest; sourcing one is the credentials
  floor). It had already moved the VM's clone to `2b747b1` (and written its `instances/local.yml`); the running
  stack was untouched. *Cost if wrong:* low: the restore reads each container's Compose labels live, so a later
  build's layout is followed; slice 3's rebuild (with a key) is where a difference would show.
- **The SSH runner's timeout is an `IsolationError`** (task 3): a hung call returns exit 124, so the restore or
  state read raises its own error instead of `subprocess.TimeoutExpired`
  (`test_vm_runner_timeout_is_an_isolation_error`). *Cost if wrong:* none found; a timeout still aborts the eval.
- The promptfoo README's *Isolation* section sits after *Run the suite* (the plan says *Running*, which the
  README does not have).

- **Review round** (one local round, #60's comment): a run now ends with an `afterAll` restore, and
  `beforeAll` refuses a new build's snapshot while `stack_dirty.json` in the hand-off directory names another
  build (override `SPE_ISOLATION_ACCEPT_DIRTY=1`): spec clarification 9. *Why:* an in-place rebuild keeps the
  volumes, so the next condition's snapshot would hold this run's state. *Cost if wrong:* ~45 s per run; a run
  that crashes before `afterAll` makes the next rebuild refuse until the stack is rebuilt clean (destroy and
  create) or the override is set. The state diff reads additions only (a known limit, part 05); a failed detail
  fetch is an `{"error": code}` entry, not a failed diff.
