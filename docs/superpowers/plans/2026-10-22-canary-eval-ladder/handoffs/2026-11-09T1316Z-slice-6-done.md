## Rulings

- **Admin entrypoint on `127.0.0.1:8443`** for operator TRS writes. *Why:* Traefik cannot tell the sandbox from the
  VM on 443 (masquerade); the sandbox's loopback is its own. *Cost if wrong:* an operator write path reachable from
  the sandbox; the hand check shows `000` from the sandbox.
- **The guard container** (`python:3.12-alpine`, stdlib `wes_guard.py`). *Why:* Traefik cannot read bodies and
  WESkit cannot refuse attachments. *Cost if wrong:* one more container on the WES write path.
- **The guard refuses ambiguous requests** (beyond the plan): repeated Content-Type/Content-Length/
  Transfer-Encoding headers, repeated parameters in Content-Type or a part's Content-Disposition, and any part
  with Content-Transfer-Encoding, all 400; it forwards the Content-Type it checked. *Why:* the local review found
  that the email parser and werkzeug read these differently, so an attachment reached WESkit past the guard.
  *Cost if wrong:* a legitimate client sending such a request gets 400; none of ours does.
- **The schema regex ends in `\Z`**, not `$` (`$` matches before a trailing newline under `re.match`).
- **`engine-environment` closed** (`api: false`) at L1: it names a file that is sourced before the engine starts.
- **The runbook stays the same at every level** (spec part 01, *Order*: L1–L3 are applied without touching the
  agent, and a runbook that varied would confound the matrix). At L1 the agent's TRS writes get 403. The
  workspace guide (`platform/instance/workspace/AGENTS.md`) now says TRS `PUT` works below L1 only.
- **Implementation per task folded into one subagent for Tasks 2–4**, with one whole-branch review after them
  instead of per-task reviews. *Why:* the plan gives the code verbatim and the tasks are sequential. *Cost if
  wrong:* none found: the whole-branch review covered all three.
