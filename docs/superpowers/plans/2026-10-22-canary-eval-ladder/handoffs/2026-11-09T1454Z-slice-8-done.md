## Rulings

- **`DOCKER-USER` rules, not an `internal: true` network** (plan). *Why:* the sandbox reaches the API by the VM's
  IP through Docker's DNAT to Traefik in another project; an internal network has no route there. *Cost if
  wrong:* rules live outside Compose; a host whose Docker uses the nftables backend needs another filter.
- **The fixed subnet `172.30.250.0/24`** (plan; free on de.NBI, Task 1). *Cost if wrong:* on a host that uses it,
  the frontend fails to start; set `spe_sandbox_subnet`/`spe_sandbox_ip` in the instance file.
- **The unroutable resolver `192.0.2.53`** (plan). *Why:* external names do not resolve, service names still
  resolve through Docker's embedded DNS. External names time out rather than fail fast: the drop rule eats the
  forwarded queries. *Cost if wrong:* a slow failure (8 s in the probes) instead of an instant one.
- **The boot-time window** (plan's residual): after a reboot, containers can start before `spe-egress.service`
  applies the rules. *Cost if wrong:* a few seconds of open egress after a reboot; no ladder run reboots.
- **No `PartOf=docker.service`** (review item 4; the plan had it). *Why:* with it, a Docker restart ran
  `ExecStop` and left egress open until the containers were back; Docker does not flush `DOCKER-USER`, so the
  rules can stay through a restart. The off path still stops the unit, whose `ExecStop` removes them. *Cost if
  wrong:* none known.
- **`spe_sandbox_ip_range: 172.30.250.128/25`** (review item 2; beyond the plan). *Why:* without it Docker could
  give `.10` to the agent while the sandbox is recreated. *Cost if wrong:* none.
- **`status` checks the jumps, and the role re-applies when it fails** (review item 1; beyond the plan). *Why:* the
  oneshot unit stays active, so a lost jump was never restored and the converge still passed.
- **The frontend is taken down to change the subnet** (plan). *Why:* Compose does not change an existing
  network's IPAM. Not tried without it. *Cost if wrong:* none: the volumes stay.
- **The receiver checked with a unique marker** (beyond the plan's fixed `spe-receiver-check`). *Why:* the log
  carries no time and slice 7's line was there. *Cost if wrong:* none: the unique marker gave 0.
- **`/etc/spe` is created by the role** (beyond the plan). *Why:* no role creates it, and `copy` does not create
  parent directories. *Cost if wrong:* none.
- **Task 2 implemented inline, not by a subagent.** *Why:* the plan gives the code verbatim. *Cost if wrong:*
  none found by the tests and the build.
